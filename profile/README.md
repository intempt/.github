# Intempt

**Agentic GTM for companies that refuse to hire their way to scale.**

7 agents. 4 products. One customer context.

Your GTM stack is five tools that don't talk. Analytics in one, creative in another, testing in a
third, sequences in a fourth, and a CRM that knows none of it. Intempt runs all four on one customer
context, with agents that do the work a specialist would.

[intempt.com](https://intempt.com) · [Docs](https://docs.intempt.com)

## SDKs

Send events, identify people, and personalize. Every SDK conforms to one API contract, so `track`,
`identify`, `group`, `alias` and `consent` mean the same thing on every platform - a profile your
web SDK builds is the same profile your server SDK writes to.

| SDK | Platform | Covers |
|---|---|---|
| [intempt-js](https://github.com/intempt/intempt-js) | Browser | Events, identity, personalization |
| [intempt-android](https://github.com/intempt/intempt-android) | Android, Kotlin and Java | Events, identity, consent, autocapture, push |
| [intempt-swift](https://github.com/intempt/intempt-swift) | iOS, tvOS, macOS, watchOS | Events, identity, consent, autocapture, APNs push |
| [intempt-reactnative](https://github.com/intempt/intempt-reactnative) | React Native | One JavaScript surface over the two native SDKs |
| [intempt-node](https://github.com/intempt/intempt-node) | Node.js | Server-side events and identity |
| [intempt-python](https://github.com/intempt/intempt-python) | Python | Server-side events and identity |
| [intempt-php](https://github.com/intempt/intempt-php) | PHP | Server-side events and identity |

Install instructions live in each SDK's README, and in the [docs](https://docs.intempt.com). Check
the repo for the version that's published before pinning one.
